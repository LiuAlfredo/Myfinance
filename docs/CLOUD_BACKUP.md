# MyFinance 加密云备份

MyFinance 继续使用本地 SQLite 作为主数据库。点击“立即上传加密备份”时，桌面端先创建一致性 SQLite 快照，再使用恢复密钥派生的 AES-256-GCM 密钥加密，最后上传密文。

## 已部署资源

- Worker：`myfinance-cloud-backup`
- Worker 地址：`https://myfinance-cloud-backup.liuzheng85857.workers.dev`
- D1：`myfinance-cloud`
- D1 ID：`fdf8e396-1580-4e95-9b97-b84dd5c03f2a`

Cloudflare 账户的 R2 订阅当前处于移除状态。为了不触发订阅或计费变更，密文按 512 KiB 分块保存在 D1。单份备份上限为 20 MiB。

## 云账号与首次使用

1. 软件启动时输入云账号和至少 12 位密码，或选择注册账号。
2. 每个账号会创建独立本地 SQLite 数据库。
3. 注册后保存软件显示的恢复密钥。
4. 新设备登录已有备份的账号时，输入原恢复密钥。
5. 登录后打开“财务 → 设置 → 加密云备份”，点击“立即上传加密备份”。

云账号密码只用于身份验证。Worker 使用带随机盐、100,000 次迭代和独立 `PASSWORD_PEPPER` Worker Secret 的 PBKDF2-HMAC-SHA256 保存密码摘要，不保存密码原文。成功登录后，桌面端获得 30 天会话令牌；本地使用现有软件数据密钥加密保存令牌，D1 只保存令牌的 SHA-256。

恢复密钥继续只负责加密和解密备份。新设备登录同一账号时仍需导入恢复密钥，服务器无法用账号密码解密财务数据。

从 v0.5.0 升级时，首次成功登录会把尚未归属账号的历史备份关联到当前账号。迁移请求只发生一次；迁移完成后的备份接口使用账号会话令牌。

## 自动备份与保留策略

配置验证成功后，自动云备份默认开启。应用在已登录且保持运行时每 5 分钟检查一次；只有业务数据发生变化，并且达到设置的最短间隔后才会创建新的加密快照。默认最短间隔为 24 小时。

- 每台设备默认保留最近 10 份自动备份。
- 最近 24 小时上传的自动备份处于保护期，允许暂时超过保留数量。
- 手动备份不会被自动清理。
- 固定的备份不会被自动清理，也不能直接删除。
- 新备份上传成功后才执行清理；清理失败不会使本次备份失效。
- 上传使用稳定的备份编号重试，网络响应丢失时不会生成重复记录。

设置页可调整间隔、保留数量和保护期，也可以先预览候选数量再执行清理。软件关闭期间不会创建新快照，下次登录后会自动补做符合条件的备份。

恢复密钥文件已被 `.gitignore` 排除，并限制为当前 Windows 用户可读。请另存一份到安全的密码管理器或离线介质。丢失该密钥后，Cloudflare 中的密文无法恢复。

## 数据边界

- 本地 SQLite 包含完整业务数据，仍可离线使用。
- D1 的 `backups` 表只保存备份元数据。
- D1 的 `backup_chunks` 表只保存客户端生成的密文。
- Worker Secret `SYNC_TOKEN_HASH` 只保存恢复密钥的 SHA-256，不保存恢复密钥原文。
- Worker Secret `PASSWORD_PEPPER` 独立于恢复密钥，D1 泄露时不能单独用于离线验证账号密码。
- D1 按 `account_id` 隔离备份；一个账号不能列出、下载、固定或删除另一个账号的备份。
- 连续 5 次登录失败后，该账号与来源组合会临时锁定 15 分钟。
- 退出登录会撤销当前会话，恢复密钥仍保留在本机加密配置中。
- 恢复操作会先备份当前本地数据库，再替换数据，并要求使用备份创建时的软件密码重新登录。

自动备份用于灾难恢复，不承担多设备逐条数据合并。多设备同步需要独立的设备身份、操作日志和冲突处理协议。
