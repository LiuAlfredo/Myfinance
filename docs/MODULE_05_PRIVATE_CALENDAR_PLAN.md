# 模块 05：私密日历开发计划

## 1. 模块定位

模块名称暂定：

```text
私密日历
```

该模块用于私密记录已经发生的亲密关系，包括：

* 发生日期和时间
* 地点
* 姓名（可直接输入任何人的名字或别名）
* 可选备注

模块采用日历作为主要入口。发生过亲密关系的日期使用不同颜色或标记显示，点击日期后可以查看当天的记录。

当前模块已进入开发阶段。

---

## 2. 核心使用流程

```text
进入私密日历
    ↓
查看月历
    ↓
有记录的日期显示特殊颜色
    ↓
点击某一天
    ↓
查看当天记录，或添加新记录
    ↓
填写时间、地点、姓名和备注
    ↓
保存到本地加密存储
```

一个日期允许保存多条记录。

---

## 3. 日历页面

### 3.1 月视图

默认显示当前月份，并支持：

* 上一个月
* 下一个月
* 返回今天
* 点击具体日期

日期显示规则：

* 没有记录：使用普通日历样式
* 有一条或多条记录：使用独立的私密标记色
* 当前选中日期：使用边框或背景强调
* 今天：保留独立的“今天”标识，避免与记录颜色混淆

日历格子只显示是否存在记录，不直接显示对象、地点或备注。

### 3.2 隐私显示

为了避免旁人从屏幕直接判断记录内容：

* 模块中心名称使用“私密日历”，不使用过于直接的名称
* 日历颜色含义只在模块内部说明
* 系统通知不显示对象、地点或具体内容
* 可增加“一键模糊”或“隐私模式”，临时隐藏记录标记

---

## 4. 日期详情

点击日期后打开侧边面板或对话框。

如果当天没有记录：

```text
当天暂无记录
[添加记录]
```

如果当天存在记录，显示：

* 时间
* 姓名或别名
* 地点
* 备注摘要
* 编辑按钮
* 删除按钮

删除记录前必须二次确认。

---

## 5. 添加和编辑记录

第一阶段字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 日期 | 是 | 默认使用当前选中的日期 |
| 时间 | 是 | 记录发生时间 |
| 姓名 | 是 | 自由输入任何人的名字或别名，不需要预先创建对象 |
| 地点 | 否 | 自由文本，例如城市、酒店或住所 |
| 备注 | 否 | 私密补充说明 |

交互要求：

* 从某个日期进入添加页面时，自动填入该日期
* 保存后立即刷新日历颜色和当天详情
* 编辑记录时保留原值
* 表单错误在对应字段附近显示
* 不允许保存无效日期或时间

第一阶段不加入照片、附件、联系人读取和位置自动获取。

---

## 6. 姓名录入

不提供对象管理或对象档案。每条记录直接输入任意姓名或别名，姓名随该条记录一起加密保存。系统不读取通讯录，也不保存电话或其他身份信息。

---

## 7. 数据模型草案

正式开发时必须通过数据库 migration 添加，不得直接删除或重建现有数据库。

### 7.1 private_calendar_events

```text
id
occurred_at
timezone
person_name（包含在加密 payload 中）
location_encrypted
note_encrypted
created_at
updated_at
```

索引建议：

```text
private_calendar_events(occurred_at)
```

模块表与 Finance 表保持完全独立，禁止与账户、交易或预算表建立外键关系。

## 8. 隐私和数据安全前置条件

这类信息属于高度敏感个人数据。正式开发前必须先完成以下安全能力：

1. 不能只依赖当前前端登录页面保护数据。
2. 私密字段不能以明文写入 SQLite。
3. 加密和解密必须在 Tauri / Rust 后端集中处理。
4. 密钥不能直接硬编码在前端代码中。
5. 应使用用户密码派生加密密钥，并为每条敏感记录使用随机 nonce。
6. 不在控制台、日志、崩溃信息或遥测中输出私密内容。
7. SQLite 备份必须包含加密数据，JSON/CSV 默认不导出该模块。
8. 如允许导出，必须由用户单独确认，并优先生成加密备份。
9. 软件退出或锁定后清除内存中的解密密钥。
10. 修改登录密码时需要安全地重新包装或迁移数据密钥，不能导致历史数据无法解密。

当前实现已使用登录密码派生密钥包装密钥，私密记录由 Rust 后端加密后写入数据库。

## 11. 开发阶段

### 阶段 1：交互原型

* 确认模块名称和隐私显示方式

### 阶段 2：加密基础

* 设计数据密钥与密码派生机制

* 实现锁定、解锁和修改密码后的密钥迁移

### 阶段 3：数据库 migration

* 新增事件表
* 添加必要索引

### 阶段 4：后端 CRUD

* 私密记录新增、编辑、删除和按日期查询

### 阶段 5：日历界面

* 月历展示
* 有记录日期的颜色标记
* 日期详情
* 添加、编辑和删除记录

### 阶段 6：备份与隐私完善

* 加密备份
* 隐私模式
* 自动锁定
* 通用、无敏感内容的错误提示

### 阶段 7：测试和验收

* 单元测试
* 数据库 migration 测试
* 加密和密码修改测试
* 跨月、闰年、时区和夏令时测试

* Light / Dark Mode 视觉检查

## 12. 第一阶段验收标准

模块只有满足以下条件后才可以标记为完成：

* 可以在日历中添加一条记录
* 可以记录日期、时间、地点、任意姓名和备注
* 有记录的日期具有清晰但克制的颜色标记
* 点击日期可以查看当天所有记录
* 可以编辑和删除记录
* 同一天可以保存多条记录
* 重启软件后记录仍然存在
* 未解锁时不能读取私密记录
* SQLite 中的敏感字段不是明文
* 修改密码后历史记录仍可正常解密
* Finance 数据和功能不受影响
* 备份与恢复不会泄露或损坏私密记录

---

## 13. 暂不实现

第一阶段暂不实现：

* 云同步
* 系统通讯录读取
* GPS 自动定位
* 照片和文件附件
* 社交分享
* 自动发送提醒给其他人
* AI 分析私密记录

这些功能涉及更大的隐私和授权范围，需要后续单独评估。

## 14. 历史日期、年度统计与流程完善

当前实现增加了以下交互：

* 点击“历史数据”或日历标题快速选择年月；点击有记录的历史年份，弹出年度统计。
* “年度统计”也可直接查看当前浏览年份，显示全年次数、记录天数和每月分布。
* 每条记录计一次，同一天多条记录分别计数；按保存的日历日期归属年份。没有记录的年份显示零。
* 点击统计弹窗中的月份返回对应月历；修改记录日期后定位到新日期。
* 固定六行月历、轻量翻月和日期详情动画，并尊重系统减少动画设置。
* 查询使用日期与刷新版本隔离，旧请求不能覆盖当前日期。加载失败显示重试入口，不沿用旧记录。
* 保存和删除防重复提交；失败保留表单或确认框，成功刷新日历与统计。
* 隐私模式隐藏日历标记、详情和统计；提供手动锁定，全局闲置 15 分钟自动退出登录并清除后端密钥。
* SQLite 备份与恢复使用 SQLite 在线备份接口处理 WAL。恢复前校验数据库并保留当前数据库副本，恢复后重新登录。
* 恢复确认明确覆盖所有模块和密码配置；需使用备份时的密码。JSON / CSV 不包含私密日历。

实现未新增明文统计表，也不向浏览器存储写入私密记录或统计结果。统计在 Rust 解锁后读取加密记录生成。

验证命令：`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`；Rust 使用 `cargo test --manifest-path src-tauri/Cargo.toml`。

前端回归测试覆盖查询乱序与失败重试、历史年份与月份导航、重复保存、跨年编辑、删除确认、隐私模式、闲置锁定及恢复登录状态。Rust 测试覆盖年度聚合、同日多条、跨年移动与删除、加密和锁定、密钥重新包装，以及存在 WAL 时的备份恢复。桌面端重启持久化与真实备份恢复仍需在具备 Rust / Tauri 构建环境的 Windows 上验收。
